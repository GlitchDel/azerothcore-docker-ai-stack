# AzerothCore (WoW 3.3.5a) + Local LLM AI Companion (Ollama & SOAP)

Развёртывание контейнеризированного игрового сервера **World of Warcraft: Wrath of the Lich King (3.3.5a)** на базе **AzerothCore** с модулем `mod-playerbots` в среде Docker (Windows + WSL2) и интеграция игрового бота-компаньона с локальной языковой моделью (**Ollama / Gemma 3**).

Ядро AzerothCore было пересобрано в Docker с интеграцией C++ модуля `mod-playerbots`, а сам AI-мост (`Ollama + SOAP`) прикручен сверху как внешний микросервис без вмешательства в исходный код сервера.

## Архитектура решения

Взаимодействие между игровым сервером внутри Docker-контейнера и локальной нейросетью на хост-машине реализовано через событийно-ориентированный Python-мост:

```text
[WoW Client 3.3.5a]
       │ (сообщение игрока в /say)
       ▼
[ac-worldserver (Docker)] ──► пишет в Chat.log (ChatLog.Enable = 1)
       │
       ▼ (чтение tail в реальном времени)
[src/tempest_ai.py (Host)]
  ├── Контекст диалога (deque + tempest_memory.json)
  ├── Запрос в Ollama API (http://127.0.0.1:11434/api/chat)
  └── Структурированный JSON-ответ: {reply, emote, action}
       │
       ▼ (HTTP POST / XML SOAP API :7878)
[ac-worldserver (Docker)]
  ├── .announce -> реплика в чат игры
  ├── .playerbots exec <bot> emote <anim> -> анимация
  └── .playerbots exec <bot> <follow|stay|attack> -> ИИ-поведение
```
## Troubleshooting & Root Cause Analysis

В ходе развёртывания и сквозного E2E-тестирования был диагностирован и устранён ряд инфраструктурных и сетевых проблем:

| Проблема | Диагностика (Root Cause) | Решение |
| :--- | :--- | :--- |
| **Конфликт портов MySQL при старте Docker** | Проверка через `netstat -ano` показала, что порты `3306` и `3307` заняты локальными службами СУБД от предыдущих проектов. | Переопределён внешний проброс `DOCKER_DB_EXTERNAL_PORT=3308` через `.env` без изменения базового `docker-compose.yml` (сохранена совместимость с upstream). |
| **Ошибка парсинга `.env`** (`unexpected character "\xff\xfe..."`) | Файл `.env`, созданный стандартными средствами Windows, сохранился в кодировке `UTF-16 LE` с BOM. | Файл пересохранён в кодировке `UTF-8` (без BOM). |
| **Клиент игнорирует `127.0.0.1` и подключается к внешним IP (`:80`)** | Инспекция активных сокетов процесса (`Get-NetTCPConnection`) выявила комплексную причину:<br>1. Библиотека `Scan.dll` перехватывала трафик.<br>2. Дубликат `realmlist.wtf` в корне `Data` перекрывал `Data\ruRU\realmlist.wtf`.<br>3. Рассинхрон адресов с `WTF\Config.wtf` (`127.0.0.2`) и сохранение файлов с BOM. | Отключён перехватчик (`Scan.dll.bak`), удалён дубликат `realmlist.wtf`, адреса синхронизированы на `127.0.0.1` в чистой кодировке ASCII, очищен каталог `Cache` и использован чистый бинарный файл `Wow.exe` (build 12340). Доступность порта `3724` подтверждена через `Test-NetConnection`. |
| **Ошибка авторизации после создания аккаунта через консоль** | Первичная запись не сбросилась в БД до перезапуска / кэш учётных записей не обновился. | Повторное создание аккаунта с принудительной фиксацией состояния в БД командой `saveall`. |
| **Таймаут первого запроса к Ollama** (`timed out`) | Холодная загрузка модели весом `7.3 GB` в ОЗУ занимала больше стандартных 30 секунд. | Таймаут HTTP-клиента увеличен до `120` секунд и добавлен параметр `"keep_alive": "30m"` для удержания модели в памяти. |
| **Повторяющиеся анимации и команды бота** | На нейтральных репликах LLM дублировала однотипные значения `"emote"` и `"action"`. | Введён трекинг `last_emote` / `last_action` на стороне Python и уточнён системный промпт. |
